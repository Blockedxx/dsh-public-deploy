## 二、踩坑记录（重要）

### 坑 1：Node 版本过低导致 CLI 静默失效

**现象**：沙箱自带 Node v22.13.1，`npm install -g @deepseek-ai/dsh` 成功（522 包），但 `dsh --version`、`dsh web --help` **全部无输出、退出码 0**，不报任何错。

**根因**：dsh 的入口 `lib/bin.js` 第 168 行：

```js
if (import.meta.main) await runCli();
```

`import.meta.main` 是较新的 Node API，**v22.13.1 尚未支持**，求值为 `undefined`（已实测确认），导致 `runCli()` 永远不被调用 —— CLI 直接静默退出。

同时安装时有 EBADENGINE 警告，三个依赖要求 `node >=22.19.0`：
- `undici@8.10.2`
- `@earendil-works/pi-ai@0.85.1`
- `@earendil-works/pi-telemetry@0.85.1`

**解决**：升级 Node 到 **v24.20.0 LTS**（满足 `^20.19 || >=22` 要求），`import.meta.main` 求值为 `true`，CLI 恢复正常。

```bash
export NVM_NODEJS_ORG_MIRROR=https://mirrors.tencent.com/nodejs-release/
nvm install 24.20.0
nvm alias default 24.20.0
```

> 注意：换 Node 版本后必须**重新全局安装** dsh，否则命令仍指向旧 Node 的 bin 目录。

### 坑 2：npm 11.19 的 allow-scripts 拦截原生依赖

npm 11.19 默认拦截依赖的 install 脚本，dsh 有 5 个包含原生/构建脚本的包被跳过：

| 包 | 用途 |
|---|---|
| `@deepseek-ai/dsh-subprocess-local` | 子进程 spawn helper |
| `koffi` | 原生 FFI |
| `node-pty` | 终端 PTY（dsh 终端工具依赖） |
| `@google/genai` | Google AI SDK |
| `protobufjs` | protobuf 运行时 |

**解决**：安装时显式放行：

```bash
npm install -g \
  --allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,@google/genai,protobufjs \
  @deepseek-ai/dsh@0.1.5-rc.1
```

验证产物已就位：
- `node-pty/prebuilds/linux-x64/pty.node` ✅
- `@koromix/koffi-linux-x64/linux_x64/koffi.node` ✅

## 三、启动方式

### 推荐：使用启动脚本

```bash
/workspace/dsh-start.sh [端口] [工作区目录]
# 例：/workspace/dsh-start.sh 3080 /workspace/dsh-workspace
```

脚本会自动：加载 Node 24 → 检查端口占用 → 后台启动 → 抓取带 token 的访问 URL 并打印。

### 手动启动

```bash
source ~/.nvm/nvm.sh && nvm use 24.20.0
cd /workspace/dsh-workspace
dsh web --no-open --port 3080
```

启动后终端会打印形如：

```
dsh web: http://127.0.0.1:3080/?token=<随机token>
```

## 四、鉴权机制（易踩坑）

dsh 的 Web UI **不是裸奔的**，有 browser-trust 防护：

| 访问方式 | 结果 |
|---|---|
| 直接访问 `http://127.0.0.1:3080/` | **HTTP 401** `dsh web authentication required` |
| 带 `?token=<启动时打印的token>` | **HTTP 303** → 置入 session cookie |
| 携带 cookie 再访问 `/` | **HTTP 200**，正常加载 UI |

**关键**：token 每次启动**随机生成**，无 CLI 参数可固定。必须用启动时打印的那个 URL 首次访问，浏览器拿到 cookie 后，后续直接访问 `127.0.0.1:3080` 即可。

实测验证：

```
1) 无 token        → HTTP 401
2) 带 token        → HTTP 303
3) 带 cookie       → HTTP 200  size=27660  <title>DeepSeek Harness</title>
4) 端口监听        → 127.0.0.1:3080 (LISTEN)
5) dsh --dump-config → 正常输出配置树
```

## 五、首次使用还需两步配置

启动后打开 Web UI，**必须完成这两步**才能跑任务：

1. **配置模型** —— `设置 → 模型`，填入 DeepSeek API Key 并保存（在 [platform.deepseek.com](https://platform.deepseek.com) 获取）。密钥写入 `~/.dsh/.credentials.yaml`，只写不回显。
   - 其他提供方：点击「添加提供方」可选 Anthropic、OpenAI 等。
2. **选择工作区** —— 点击「选择工作区」，添加并选中启动 dsh 时所在的目录。**未选中前会话输入框不可用。**

## 六、常用命令

```bash
dsh web --port 8080          # 换端口
dsh web --no-open            # 不自动开浏览器
dsh --profile web --dump-config   # 导出实际配置树（排查插件加载）
dsh plugin --profile web add <pkg>  # 装插件（转发给 pnpm）
```

> **❌ 不要用 `dsh web --host 0.0.0.0`**
> 早期版本的本文档把它列进了常用命令，这是错的 —— `dsh` **刻意拒绝**绑定非 loopback：
>
> ```
> $ dsh web --host 0.0.0.0 --port 13099
> error: --host 0.0.0.0 is intentionally not supported yet for safety:
>        it would expose remote code execution to the network; use 127.0.0.1 instead
> ```
>
> 它只能绑 `127.0.0.1`。想让公网访问，用本仓库的桥接层（见 README 第 9 节），
> 而不是试图改它的监听地址。

## 七、环境说明

- `registry.npmjs.org` 在**部分**沙箱里会解析到 `198.18.0.23`（RFC 2544 保留段的虚假 IP）导致不通；但**并非所有沙箱都如此** —— 2026-09-18 复现时该域名直连返回 200，无需镜像即装完 520 个包。装之前可以先探一下，不通再切镜像：
  ```bash
  curl -s -o /dev/null -w '%{http_code}\n' --max-time 10 https://registry.npmjs.org/@deepseek-ai/dsh
  # 000 → 切镜像：npm config set registry https://registry.npmmirror.com
  ```
- Node 二进制同样从腾讯镜像下载，sha256 校验通过。
- `dsh web` 默认绑定 `127.0.0.1`，仅本机可访问。
